# عدسة — مدونة React تعليمية

**عدسة** مشروع واجهة مدونة تعليمي مبني بـ **React + Vite + JavaScript + CSS**، ومن غير استخدام APIs. الفكرة إننا نمثل صفحات المدونة المطلوبة محليًا ببيانات وصور موجودة داخل المشروع، عشان يبقى سهل الفهم والتشغيل والتجربة للمبتدئ.

المشروع **محاكاة للصفحات المطلوبة** وليس نسخة مطابقة pixel-perfect للتصميم المرجعي. الهدف هو تنفيذ الهيكل والتصفح وتجربة المدونة بشكل واضح وقابل للتعلم.

## التشغيل

ثبّت Node.js إصدار 22.12 أو أحدث، وفك ضغط المشروع في مجلد مستقل. افتح المجلد في VS Code ثم افتح Terminal داخله. لا تفتح `index.html` مباشرة، لأن React يحتاج سيرفر Vite.

من داخل مجلد المشروع شغّل الأوامر دي بالترتيب:

```bash
npm install
npm run dev
```

سيرفر التطوير يعمل على المنفذ **3000**. بعد تشغيله افتح عنوان localhost الذي يظهر في الطرفية.

لبناء نسخة الإنتاج:

```bash
npm run build
```

ولمعاينة نسخة الإنتاج محليًا:

```bash
npm run preview
```

## شكل المشروع ووظيفة كل جزء

- `src/main.jsx`: نقطة بداية React، وفيها `BrowserRouter` الذي يتيح التنقل بين روابط الصفحات بدون إعادة تحميل كاملة للمتصفح.
- `src/App.jsx`: تعريف الـ Routes الأساسية للموقع:
  - `/` للصفحة الرئيسية.
  - `/blog` لصفحة المدونة.
  - `/blog/:slug` لتفاصيل تدوينة معينة.
  - `/about` لصفحة من نحن.
  - `*` لأي مسار غير معروف، ويعرض صفحة NotFound.
- `src/components/`: مكونات واجهة صغيرة قابلة لإعادة الاستخدام:
  - `Navbar.jsx`: شريط التنقل.
  - `Footer.jsx`: تذييل الموقع وروابط التصنيفات.
  - `PostCard.jsx`: بطاقة عرض التدوينة.
  - `Author.jsx`: بيانات الكاتب أو صورة المؤلف.
  - `Pagination.jsx`: أزرار التنقل بين صفحات النتائج.
  - `ScrollToTop.jsx`: يرجّع الصفحة لأعلى عند تغيير المسار.
  - `Newsletter.jsx`: واجهة تجريبية للاشتراك في النشرة.
  - `Icon.jsx`: عرض الأيقونات المستخدمة في الواجهة.
  - `SectionHeading.jsx`: عنوان موحّد للأقسام.
- `src/pages/`: الصفحات الكبيرة التي تجمع المكونات وتحدد محتوى كل route:
  - `Home.jsx`: الصفحة الرئيسية.
  - `Blog.jsx`: قائمة المدونة والبحث والتصنيف والتصفح بين الصفحات.
  - `BlogDetails.jsx`: تفاصيل تدوينة واحدة.
  - `About.jsx`: صفحة من نحن، وتحاكي صفحة المرجع بمقدمة «مهمتنا هي الإعلام والإلهام»، وإحصائيات العرض، وقيمنا الأربعة، وفريق الكتاب، وقسم التواصل.
  - `NotFound.jsx`: صفحة المسار غير الموجود.
- `src/data/posts.json`: البيانات المحلية، وفيه **28 تدوينة** مع `categories` و`siteInfo`. صور التدوينات تم تنزيلها محليًا من روابط الأصول الموجودة في JSON، مع الحفاظ على ملف JSON الأصلي كما هو.
- `src/index.css`: كل تنسيقات CSS العامة للموقع، مثل الألوان والتخطيط والخطوط والاستجابة للشاشات المختلفة.
- `src/about.css`: تنسيقات صفحة About المستقلة عن تخطيط الصفحات الأخرى.
- `src/utils/formatDate.js`: دالة مساعدة لتنسيق تاريخ التدوينة قبل عرضه للمستخدم.
- `public/images/`: الأصول والصور المحلية التي تُعرض داخل الواجهة، ومنها صور التدوينات والمؤلفين والشعار عند توفرها.

## منطق التصفح والـ Routing

`BrowserRouter` يتابع عنوان الصفحة الحالي، و`Routes` يختار الصفحة المناسبة بناءً على المسار. استخدام `Link` أو روابط React Router يجعل الانتقال بين الرئيسية والمدونة والتفاصيل سريعًا من غير تحميل صفحة HTML جديدة كل مرة.

المسار `/blog/:slug` فيه جزء متغير اسمه `slug`. في `BlogDetails.jsx` نستخدم `useParams` لقراءة قيمة الـ slug من عنوان المتصفح، وبعد كده نبحث في بيانات التدوينات عن التدوينة المطابقة. لو مفيش تدوينة مطابقة، الصفحة تتعامل مع الحالة باعتبارها غير موجودة بدل ما تعرض محتوى غلط.

أي مسار غير معروف يطابق `*` ويعرض `NotFound.jsx`. كده تجربة المستخدم تفضل مفهومة حتى لو كتب رابطًا غير موجود يدويًا.

صفحة `/about` تعرض تعريفًا بسيطًا بالموقع يحاكي المرجع https://adasa-psi.vercel.app/about: مقدمة «مهمتنا هي الإعلام والإلهام»، وإحصائيات العرض المرجعية، وقيمنا الأربعة، وفريق الكتاب وعدده 28، ثم قسم التواصل. أرقام الإحصائيات الكبيرة محاكاة للمرجع وليست عدّادًا فعليًا.

في `About.jsx` يتم استخدام `data.posts.filter` مع `findIndex` لمنع تكرار اسم الكاتب في قائمة الفريق. صور الكتاب أصلية ومحلية من `public/images/authors/id.jpg`. أزرار السوشيال تفتح حسابات عدسة العامة القادمة من `siteInfo.social`، وليست حسابات شخصية للكتاب لأن JSON لا يوفرها؛ والروابط الأصلية للكتاب تظل `#`.

روابط «من نحن» في `Navbar` و`Footer` تفتح `/about`، كما أن زر «اعرف المزيد» في الصفحة الرئيسية يفتح المسار نفسه. وتُظهر الواجهة حالة active في الهيدر عند فتح صفحة من نحن.

## منطق صفحة Blog

صفحة `Blog.jsx` بتجمع أكثر من خطوة بسيطة:

1. تستخدم `useState` لحفظ نص البحث، ورقم الصفحة الحالي، ونوع العرض المختار (مثل شكل الشبكة أو القائمة حسب الواجهة).
2. تستخدم `useSearchParams` لقراءة التصنيف من query string، مثل `?category=إضاءة`. ده يخلي روابط التصنيفات القادمة من `Home` أو `Footer` تفتح نفس صفحة المدونة وهي مفلترة، وكمان يحافظ على الحالة في **browser history**؛ لذلك زرّي Back وForward يشتغلوا بشكل طبيعي.
3. تبدأ بتصفية البيانات باستخدام `filter`: التدوينات التي تطابق البحث والتصنيف فقط تفضل في النتائج. البحث ممكن يطابق العنوان أو البيانات النصية التي تعرضها الواجهة، والتصنيف يعتمد على `categories` الموجودة في JSON.
4. بعد التصفية، تستخدم `slice` لاختيار الجزء الخاص بالصفحة الحالية فقط. عدد النتائج في الصفحة هو **6 تدوينات**.
5. `map` يحوّل كل تدوينة ظاهرة إلى `PostCard`، بدل تكرار نفس markup يدويًا لكل تدوينة.
6. عدد صفحات النتائج يُحسب باستخدام `Math.ceil` حتى يتم تقريب العدد لأعلى. مثلًا، لو عدد النتائج 13 ونعرض 6 في الصفحة، يبقى عندنا 3 صفحات: صفحتان كاملتان وصفحة أخيرة فيها تدوينة واحدة.

عند تغيير البحث أو التصنيف، المفروض يرجع رقم الصفحة للبداية حتى لا يظل المستخدم على صفحة متأخرة لا تحتوي نتائج بعد التصفية. وعند عدم وجود نتائج، تعرض الصفحة حالة واضحة بدل مساحة فارغة.

## تفاصيل التدوينة

`BlogDetails.jsx` يستخدم `useParams` للوصول إلى `slug`، ثم يستخدم `find` لإيجاد التدوينة المقابلة داخل `posts.json`.

محتوى التدوينة النصي محفوظ كسلسلة واحدة. يتم تقسيمه إلى فقرات باستخدام `content.split('\n\n')`، أي أن كل سطرين جديدين يفصلان فقرة عن الأخرى. العناوين داخل المحتوى تبدأ بـ `##`، لذلك يمكن تمييزها وعرضها كعناوين فرعية بدل عرضها كنص عادي.

صور التدوينات والمؤلفين محلية داخل المشروع، والمكونات تستدعيها بالمسارات التالية:

```jsx
// صورة التدوينة
<img src={`/images/posts/${post.id}.jpg`} alt={post.title} />
// صورة الكاتب
<img src={`/images/authors/${post.id}.jpg`} alt={post.author.name} />
```

بهذا الشكل الواجهة لا تعتمد على تحميل الصور وقت التشغيل من API أو من رابط خارجي.

## الفرق بين المكونات والصفحات

**المكوّنات (components)** هي أجزاء صغيرة تتكرر أو لها وظيفة محددة، مثل بطاقة تدوينة أو شريط التنقل. المكوّن غالبًا يستقبل بيانات عبر props ويمكن استخدامه في أكثر من صفحة.

**الصفحات (pages)** هي شاشات كاملة مرتبطة بالـ routes. الصفحة تجمع عدة مكونات معًا وتقرر أي بيانات ومنطق يظهر في عنوان معين، مثل صفحة المدونة أو تفاصيل تدوينة.

## حدود النطاق

- لا توجد APIs أو قاعدة بيانات أو تخزين خارجي؛ البيانات محلية في `src/data/posts.json`.
- `Newsletter.jsx` واجهة تجريبية فقط: لا يوجد إرسال فعلي، ولا تخزين للبريد، ولا تكامل مع خدمة اشتراك.
- صفحة `about` منفذة الآن، بينما صفحتا `privacy` و`terms` ما زالتا غير منفذتين.
- أرقام المقدمة الكبيرة متروكة مثل الموقع المرجعي. عدد المقالات الفعلي 28، وأعداد كل تصنيف في بطاقات التصنيفات محسوبة من التدوينات نفسها، وليس من حقل `count` القديم في JSON.

الفلاتر هنا قائمة `select` فعلية، مش Navs أو Tabs. النتيجة تشبه الموقع المرجعي لكن مكان التصفية مختلف عمدًا عشان يلتزم بالواجب.

## تجربة يدوية قصيرة

1. شغّل `npm install` ثم `npm run dev`، وافتح المنفذ 3000.
2. من الصفحة الرئيسية اضغط رابطًا للمدونة أو تصنيفًا من الصفحة الرئيسية/الفوتر، وتأكد أن `/blog?category=...` يعرض التصفية.
3. اكتب كلمة في البحث وتأكد أن النتائج تتغير وأن عرض 6 تدوينات فقط في الصفحة.
4. جرّب أزرار Pagination، ثم استخدم Back وForward في المتصفح وتأكد أن التصنيف والروابط يتنقلان بشكل صحيح.
5. افتح بطاقة تدوينة وتأكد أن الرابط يأخذك إلى `/blog/:slug` وأن العناوين التي تبدأ بـ `##` تظهر كعناوين فرعية.
6. افتح مسارًا عشوائيًا مثل `/anything` وتأكد من ظهور `NotFound`.
7. جرّب زر النشرة؛ المطلوب هنا اختبار شكل الواجهة فقط، لأن الاشتراك تجريبي ولا يرسل أو يخزن بيانات.
8. افتح `/about` أو اضغط «من نحن» من الهيدر/الفوتر و«اعرف المزيد» من الرئيسية، وتأكد من ظهور حالة active في الهيدر، وعدم تكرار أسماء الكتاب، وظهور أزرار السوشيال العامة وقسم التواصل.
9. أخيرًا شغّل `npm run build` للتأكد أن نسخة الإنتاج تُبنى بدون أخطاء، ثم `npm run preview` لمعاينتها.
